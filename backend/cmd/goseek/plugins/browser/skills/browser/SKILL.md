# browser

隔离浏览器操作。当用户要求打开网页、查看页面内容、点击页面元素、填表时使用。

## 前提

- 你操作的是一个**独立的 headless Chromium 实例**（独立用户数据目录），
  与用户正在使用的浏览器完全不互通。但它是**常驻的**——你打开的页面在
  命令之间保持存在，用户可以在侧边栏实时看到和点击这些页面。
- 每次带 URL 的 screenshot 会**打开一个新页面（tab）**，旧页面不会被关掉。
  用户在侧边栏能看到所有打开的页面，像浏览器的 tab 一样排列。
- 工具观察里的图片（截图）会直接出现在你的上下文里——你能"看到"它，
  不需要用 read_file 或 bash 读文件内容。

## 可用命令（已注入 PATH）

### goseek-browser screenshot <output_path> [url] [wait_seconds]

截取当前页面全图（或先打开 URL 再截屏），保存为 PNG 并返回图片标记。

- `output_path`：截图保存路径（用 /tmp 即可）
- `url`：可选。传了就先在隔离浏览器里打开这个 URL 再截屏
- `wait_seconds`：可选。页面加载等待秒数，默认 3

### goseek-browser read-page

读取当前页面的可交互元素（链接、按钮、输入框），按编号列出。
输出格式：`编号 | 标签 | 文本 | 位置`。编号可直接给 click / type。

**编号不保证跨操作稳定**：每次操作（点击、输入、页面切换、面板刷新）都可能
让编号重排。**每次操作前必须重新 read-page，用当次的编号**，不要记住上一次
的编号复用——那会点错元素。

### goseek-browser click <编号>

按编号点击元素（自动滚到可见位置）。

### goseek-browser type <编号> <文本>

向指定输入框填入文本。

## 操作流程

1. `goseek-browser screenshot /tmp/page.png https://example.com 3` 打开页面并截图；
2. 看截图，理解页面结构；
3. `goseek-browser read-page` 拿到元素编号；
4. `goseek-browser click <编号>` 点击目标元素；
5. **点击筛选器或切换页面后必须等几秒再截图**（Grafana 等页面渲染和写回
   URL 有延迟；click 命令已内置 2 秒短等，但下拉选中、面板刷新等可能需要
   更久——先 sleep 3~5 再 screenshot）；
6. `goseek-browser screenshot /tmp/after.png` 再截屏确认效果，循环直到任务完成。

## 安全

- 每次点击前描述你要点的东西，让用户知道你在做什么；
- 不要点击"删除"、"确认支付"等不可逆操作的按钮，除非用户明确要求；
- 你的操作只影响隔离浏览器实例，不会动用户正在使用的浏览器。

## 实战纪律（真机踩坑沉淀）

- **URL 参数优先于表单交互**：搜索类场景直接导航到带查询参数的 URL
  （如 `baidu.com/s?wd=关键词`、`hn.algolia.com/?q=关键词`），比"找输入框→
  focus→逐字输入→点按钮"少一半步骤，且不会触发输入框相关的交互故障；
- **验证码/人机验证 = 立即停止**：页面跳到滑块验证、reCAPTCHA 等人机验证时，
  不要尝试绕过——那是对抗网站风控。告知用户，请用户在截图上手动完成或换
  途径（如换搜索引擎）；
- **"Sorry." 或空白结果页**：先区分"没有结果"（搜索框还在）和"被拒"（整页
  只有一行字）。前者如实报告零结果；后者不要用同一个 URL 反复重试；
- **渲染等待**：SPA/结果页首屏常为空白（客户端渲染），固定 sleep 不可靠——
  截一张看，空白就等 3~5 秒重截；重要操作前后各截一张便于对比；
- **隐藏元素陷阱**：read-page 会列出 0x0 尺寸的隐藏输入框（表单字段）。
  对它们执行 type 会卡死。选择目标时核对位置列，跳过 0x0 与明显是隐藏
  字段的条目（文本是 "utf-8"、"1" 之类的表单参数）。
